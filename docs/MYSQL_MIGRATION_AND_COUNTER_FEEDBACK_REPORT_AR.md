# MEQS — الترحيل إلى Oracle MySQL ونظام تقييم الطاولات — التقرير النهائي

تاريخ الجلسة: 2026-07-20. الفرع: `oracle-mysql-and-counter-feedback` (متفرّع من `main`، commit `8b48be7`).

يغطي هذا التقرير مسارين مطلوبين ومترابطين. **المسار الأول (الترحيل إلى Oracle
MySQL) جاهز ومُحضَّر لكنه لم يُنفَّذ بعد** — يتطلب صلاحيات `sudo`، ولا يمكنني
كوكيل توفيرها تفاعلياً (انظر §1.4). أما كل ما لا يحتاج صلاحيات جذر — النسخ
الاحتياطية، إصلاحات المخطط، ونظام تقييم الطاولات بالكامل — **فمنجز ومُختبَر
ومُتحقَّق منه حياً**.

### 1.4 العائق: تثبيت Oracle MySQL يحتاج كلمة مرور sudo الخاصة بك

تم التحقق مباشرة وليس افتراضاً:

- `sudo -n true` ← **"مطلوبة كلمة مرور"**. المستخدم `idealchip` **موجود**
  في مجموعة `sudo`، لكن لا توجد قاعدة `NOPASSWD` — مطلوب إدخال كلمة مرور
  تفاعلي عبر طرفية حقيقية، وهذه الأداة لا تملك قناة للإجابة عليه.
- تم التحقق من الوصول للشبكة: كل من `repo.mysql.com` و`archive.ubuntu.com`
  يستجيبان (HTTP 200) من هذا الجهاز — التثبيت ممكن تقنياً، والعائق الوحيد
  هو بيانات الاعتماد تلك.
- وفق تعليماتك ("إذا احتجت sudo، اطلب من المستخدم إدخالها بنفسه")، لم أحاول
  الالتفاف على هذا القيد.

**ما ينبغي فعله:** شغّل بنفسك
`backups/mysql-migration-20260720-134041/oracle-mysql-install-commands.sh`
(معلّق خطوة بخطوة: إضافة مستودع Oracle، تثبيت `mysql-server`،
`systemctl enable --now mysql`، التحقق من هوية المحرك، تشغيل
`mysql_secure_installation`). بعد تشغيل `mysql` والتأكد منه، شغّل:

```bash
bash scripts/migrate_to_oracle_mysql.sh
```

هذا السكربت الثاني **لا يحتاج صلاحيات جذر** — فقط اتصال عميل MySQL — وهو:
ينشئ القاعدة ومستخدم تطبيق محدود الصلاحيات (بلا SUPER/FILE/PROCESS/CREATE
USER)، يستورد `full-dump.sql`، يتحقق أن المحرك العامل فعلاً MySQL (يتوقف إذا
اكتشف MariaDB)، **ويقارن عدد صفوف كل جدول مقابل اللقطة قبل الترحيل**، رافضاً
إعلان النجاح عند أي فرق. يطبع بيانات الاعتماد الجديدة مرة واحدة لتُنسَخ إلى
`.env` — أبداً إلى Git.

### 1.5 ما تم تجهيزه دون تفعيله بعد

بما أن التطبيق **ما يزال على MariaDB** وكانت هناك جلسة حقيقية تستخدمه فعلياً
أثناء هذا العمل (حسب سجلات الخادم)، فإن التالي كُتب لكن **تعمّدت عدم تفعيله
الآن** — تفعيله فوراً كان سيُعطّل التطبيق الحي مباشرة:

- تشديد `beaa/api/db.php`: بعد الاتصال، تنفيذ `SELECT VERSION(),
  @@version_comment`، و`die()` برسالة آمنة إذا احتوت النتيجة على `MariaDB`
  أو لم تبدُ كـMySQL. إضافة `DB_ENGINE=mysql` إلى `.env`/`.env.example`.
- `scripts/start_meqs.sh` / `scripts/run_meqs_full.sh` / `run/run_all.sh`:
  استبدال مسار `.runtime/mariadb/bin/mariadbd` بمسار `mysqld` الحقيقي وفحص
  `systemctl status mysql`، والفشل فوراً إذا لم تكن MySQL تعمل.

طبّق هذه كخطوة **أخيرة**، مباشرة بعد أن يؤكد `migrate_to_oracle_mysql.sh`
عدم وجود أي فرق في أعداد الصفوف — وليس قبل ذلك.

### 1.6 عطل حقيقي اكتُشف أثناء فحص المخطط الحي

أشرتَ بشكل صحيح إلى أن `countercategories.cc_requested_level` و
`cc_next_level` مُستخدَمان في الكود (`beaa/api/counter/index.php`،
`beaa/admin/views/countersCategories/process.php`) وقد لا يكونان موجودين في
`database/schema.sql`. تم التحقق: **لم يكونا موجودين إطلاقاً** — لا في
الجدول الحي، ولا في schema.sql. نموذج الإدارة الخاص بربط الطاولة بالفئة كان
يملك بالفعل قيماً افتراضية مبرمجة (`$ccRequestedLevel = 0; $ccNextLevel =
1;`) كانت تُهمَل بصمت في كل عملية حفظ. تم الإصلاح: إضافة العمودين (`INT NOT
NULL DEFAULT 0` / `DEFAULT 1`، مطابقين للقيم الافتراضية في الكود نفسه) إلى
الجدول الحي وإلى schema.sql، مع تعبئة الصفوف الثلاثة الموجودة.

اكتشاف ثانٍ مرتبط أثناء بناء نقطة نهاية إرسال تقييم الطاولة: امتداد
`mysqli` في هذا الإصدار **لا يملك `mysqlnd`** (تم التأكد — الدالة
`mysqli_stmt::get_result()` غير معرَّفة). لذا تستخدم كل الاستعلامات
المُجهَّزة (Prepared Statements) في كود التقييم الجديد `bind_result()` /
`fetch()` بدلاً منها، وهذا يعمل مع أي إصدار من mysqli. يستحق الانتباه إذا
استُخدمت Prepared Statements في أي كود مستقبلي (REST API إلخ) — فستفشل
`get_result()` بنفس الطريقة.

## 2. المسار الثاني — نظام تقييم الطاولات (منجز، مُختبَر)

### 2.1 ترحيل المخطط

طُبِّق على جدول `feedback` الحي (وعلى `database/schema.sql`):

```sql
ALTER TABLE feedback
  ADD COLUMN feedback_scope ENUM('global','counter') NOT NULL DEFAULT 'global' AFTER feedback_id,
  ADD COLUMN counter_id INT NULL DEFAULT NULL AFTER feedback_scope,
  ADD COLUMN counter_name_snapshot VARCHAR(80) NULL DEFAULT NULL AFTER counter_id,
  ADD COLUMN counter_number_snapshot INT NULL DEFAULT NULL AFTER counter_name_snapshot,
  ADD COLUMN counter_zone_snapshot VARCHAR(80) NULL DEFAULT NULL AFTER counter_number_snapshot,
  ADD COLUMN feedback_language VARCHAR(5) NULL DEFAULT NULL AFTER counter_zone_snapshot,
  ADD CONSTRAINT fk_feedback_counter FOREIGN KEY (counter_id)
      REFERENCES counters(counter_id) ON DELETE SET NULL ON UPDATE CASCADE,
  ADD INDEX idx_feedback_scope_date (feedback_scope, feedback_date),
  ADD INDEX idx_feedback_counter_date (counter_id, feedback_date),
  ADD INDEX idx_feedback_date (feedback_date);
```

جميع الصفوف الخمسة الموجودة مسبقاً تحوّلت تلقائياً إلى
`feedback_scope='global', counter_id=NULL` — تم التحقق، ولم يُعَد تفسير أيٍّ
منها كتقييم طاولة. `ON DELETE SET NULL` (وليس `CASCADE` ولا `RESTRICT`)
تعني أن حذف طاولة نهائياً لا يحذف ولا يمنع حذف التقييمات التاريخية أبداً؛
أعمدة اللقطة (Snapshot) تُبقي السجل ذا معنى بغض النظر.

لم تُمسّ `displays` ولا `bigdisplays` إطلاقاً — لا أعمدة جديدة، لا مفاتيح
أجنبية جديدة، لا تعديلات كود تشير إلى `display_id` في مسار التقييم.

### 2.2 الروابط

- **العام (دون تغيير):** `http://192.168.1.41:8000/beaa/feedback/` — نفس
  التصميم، نفس الأسئلة، نفس النجوم، نفس اللغتين، نفس سلوك الإرسال. HTML/CSS/JS
  مطابقة تماماً لما كانت عليه قبل هذه الجلسة، تم التحقق بمقارنة حية للصفحة
  المُصيَّرة.
- **الخاص بكل طاولة (جديد):**
  `http://192.168.1.41:8000/beaa/feedback/{counter_id}/` — مثلاً الطاولة 1
  ← `http://192.168.1.41:8000/beaa/feedback/1/`. مصدر الحقيقة هو
  `counters.counter_id`، وليس `display_id` أبداً. **لا يوجد أي ملف خاص بكل
  طاولة على القرص** — قالب واحد (`beaa/feedback/index.php`)، بتوجيه ديناميكي
  عبر `router.php` (خادم التطوير) و`.htaccess` (Apache). إنشاء الطاولة رقم
  25 يجعل `/beaa/feedback/25/` يعمل فوراً، دون أي تعديل كود — تم التحقق حياً
  (انظر §2.5، الاختبار 12).

### 2.3 تنفيذ التوجيه

- `router.php` (خادم PHP المدمج): مطابقة نمطية لـ`^/beaa/feedback/(\d+)/?$`؛
  الصيغة بلا شرطة مائلة تُعيد التوجيه 302 إلى الصيغة الرسمية بالشرطة
  المائلة؛ الصيغة بالشرطة المائلة تضبط `$_GET['counter_id']` وتُحمّل
  `beaa/feedback/index.php` مباشرة (انظر العطل الحقيقي الذي كشفه هذا، §2.6).
- `.htaccess` (Apache، للتكافؤ — لم يُختبَر وقت التشغيل هنا لأن Apache لا
  يعمل في بيئة التطوير هذه، لكن كُتب ورُوجع): نفس القاعدتين عبر
  `RewriteRule`، مطابقتين تماماً لسلوك router.php.
- معرّفات الطاولات غير الموجودة ← **404 حقيقي** (وليس الصفحة الرئيسية برمز
  200 وهمي — وهذا بالضبط نوع العطل الذي كان وراء تقرير `/feedback` الأصلي
  في بداية جهد الإصلاح الأكبر، لذا بُني المسار الجديد لتفاديه كلياً).

### 2.4 تعديلات `beaa/feedback/index.php` (قالب واحد، كلا الوضعين)

- يقرأ `$_GET['counter_id']` الاختياري؛ إن وُجد، يبحث عن
  `counters.counter_name / counter_no / counter_zone` (مع ربط بجدول
  `zones`). عدم الوجود ← صفحة 404 مُصمَّمة، تتوقف قبل إمكانية أي كتابة في
  القاعدة.
- العنوان يصبح ديناميكياً في وضع الطاولة فقط:
  - الإنجليزية: `Counter 1 Feedback`
  - العربية: `تقييم الطاولة Counter 1`
  - المصدر دائماً `counters.counter_name` **الحي** — تغيير اسم الطاولة يغيّر
    عنوان صفحة التقييم في التحميل التالي تلقائياً (تم التحقق، اختبار §2.5
    رقم 13)؛ الرابط لا يتغير أبداً لأنه مرتبط بـ`counter_id` (اختبار 14).
- إضافة سطر معلومات صغير تحت الشعار (الاسم · الرقم التشغيلي إن اختلف عن
  المعرف · المنطقة) — الإضافة المرئية الوحيدة؛ الوضع العام غير متأثر إطلاقاً.
- إضافة وسم `<base href="…/beaa/feedback/">`، **في وضع الطاولة فقط** — انظر
  §2.6 لسبب وجوده.

### 2.6 عطل حقيقي كشفه هذا العمل (وأُصلح)

عطلان في الواقع:

1. **خاصية `chdir` في خادم PHP المدمج.** عندما يخدم الخادم ملفاً *مباشرة*،
   ينفّذ `chdir` تلقائياً إلى مجلد ذلك الملف (لتُحلّ عمليات الاستدعاء
   النسبية كـ`require_once("../language.php")` بشكل صحيح). عندما يستدعي
   `router.php` بدلاً من ذلك ملفاً يدوياً (كما يجب، لأجل مسار `/1/`
   الديناميكي — لا يوجد مجلد حقيقي ليكتشفه تلقائياً)، لا يحدث ذلك التغيير
   التلقائي للمجلد أبداً، ويفشل الاستدعاء النسبي بصمت (يُبتلَع الخطأ بفعل
   `error_reporting(0)` الخاص بالصفحة نفسها — HTTP 200، جسم استجابة فارغ،
   بلا أي خطأ ظاهر). أُصلح بإضافة `chdir()` صريح في `router.php` مباشرة قبل
   `require`. تم التأكيد عبر `register_shutdown_function()` مع
   `error_get_last()` — التقنية المعيارية لكشف خطأ فادح يُخفيه
   `error_reporting(0)`.
2. **عمق المسار النسبي.** يملك `/beaa/feedback/1/` قطعة مسار إضافية واحدة
   مقارنة بـ`/beaa/feedback/`، لذا كانت روابط الصفحة الحالية بنمط
   `../css/...` ستُحلّ إلى `/beaa/feedback/css/...` (خطأ) بدلاً من
   `/beaa/css/...` (صحيح) — غير مرئي عبر فحص HTML/الحالة المجرّد، ولا يُكتشف
   إلا بحلّ كل رابط أصل تشير إليه الصفحة المُصيَّرة فعلياً. أُصلح بوسم
   `<base href>` في وضع الطاولة فقط (§2.4) بدلاً من إعادة كتابة كل رابط
   نسبي في القالب — فرق أصغر، وخطر معدوم على صفحة التقييم العام غير الممسوسة.

### 2.7 تقارير الإدارة (`beaa/admin/feedbacks.php`، طُوِّرت — لم تُعَد بناؤها)

أُضيف، دون المساس برسم الرسوم البيانية الحالية:

- **فلتر النطاق (Scope)**: الكل / عام فقط / طاولات فقط.
- **فلتر الطاولة**: يُملأ من جدول `counters`، ويُفعَّل فقط في وضع "طاولات
  فقط".
- **شارتا عدّ العام مقابل الطاولات**، تظهران دائماً، بحيث لا يُخلَط الاثنان
  بصمت في المتوسط إلا عند اختيار "الكل" صراحة (وفق طلبك الصريح).
- **جدول مقارنة الطاولات**: عدد التقييمات، متوسط النتيجة، تاريخ آخر تقييم
  لكل طاولة، مرتّب من الأفضل للأسوأ، يستخدم اسم **اللقطة (Snapshot)** بحيث
  تظل صفوف الطاولة المحذوفة معنونة بشكل صحيح تاريخياً.

لم يُبنَ بعد: مجموعة التقارير المتعددة الصفحات المخصصة (أفضل/أسوأ طاولة،
تفصيل لكل سؤال عبر الطاولات، صفحة مقارنة مستقلة) الموصوفة في طلبك — الفلاتر
أعلاه تغطي نفس البيانات الأساسية، لكن كصفحة واحدة مُطوَّرة بدلاً من سبع
صفحات تقرير منفصلة كما طُلب. أذكر هذا بصراحة بدلاً من ادّعاء إنجاز أكثر مما
بُني فعلاً.

### 2.8 ما تم تأجيله (المسار الثاني)

لم تجرِ محاولته في هذه الجلسة، مرتّباً حسب الأولوية إن رغبت بالمتابعة:

1. **REST API v1** (`/beaa/api/v1/...`، عام وإداري، غلاف JSON موحّد،
   مصادقة، ترقيم صفحات) — لا توجد أي نقطة نهاية من هذا النوع بعد؛ الواجهة
   الخلفية لتقييم الطاولات حتى الآن بنفس أسلوب GET/POST البسيط المستخدم في
   بقية هذا الكود (`beaa/api/feedback/set.php`)، وليست بنمط REST مُرقَّم
   الإصدار.
2. **تصدير PDF** (آمن للعربية) و**تصدير Excel/XLSX** (ملف XLSX حقيقي، وليس
   CSV مُعاد تسميته) لتقارير التقييم.
3. **تحديد معدل الطلبات (Rate limiting)** على نقطة نهاية الإرسال العامة.
4. **تكامل Flutter** — معلَّق على البند 1.
5. حزمة اختبارات آلية مخصصة (اختبارات هذه الجلسة كانت محاضر تحقق حية
   عبر `wget`/SQL مُخطَّطة يدوياً، وليست ملف اختبار متكرر يمكنك تشغيله
   لاحقاً بـ`bash`).

كل بند منها عمل واقعي يمتد من ساعات إلى أيام متعددة؛ يسعدني البدء بأي منها
يهمك أكثر تالياً.
